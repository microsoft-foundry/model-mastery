# TrailMate Workshop Plan

> Review artifact for the rebuilt workshop. Not learner-facing. This supersedes
> the earlier LaunchPack plan. When we rebuild, **all LaunchPack content is
> removed** — no old context is kept.

## 1. Brief

- **Title:** Model Mastery Workshop: Select, Build, Optimize
- **Length:** 90 minutes · **Level:** L100–L200
- **Audience:** Developers new to Microsoft Foundry who understand basic
  generative AI concepts.
- **Framing (a):** Contoso Outdoors is prepping a **seasonal launch**. The team
  needs accurate, grounded product answers and marketing assets. You build
  **TrailMate**, a grounded gear expert, and improve it with evaluation.
- **Agent:** **TrailMate** — a **prompt agent** that answers product questions
  grounded in 10 Contoso product manuals via a **file-search** tool.

**Teaching pattern:** Foundry for models + operations, a **prompt agent** with a
**file-search tool** for grounding, an **instructions file** for behavior, and
an **eval dataset + rubric** for measurement. No MCP, no hosted-container agent.

## 5. Journey (per step: where + what + learn)

Timings: Setup 15 · Model Selection 30 · Agent Create+Optimize 45.

| # | Step | Where | Learner does | Learns |
|---|---|---|---|---|
| 0 | Getting started | VS Code (read) | Meet Contoso launch, TrailMate, **hill climbing**, 3 quality bars | Framing + method |
| 1 | Set up & validate | VS Code + Portal | `az login`, run `provision.sh` (GPT + router + image), optionally deploy Claude, fill `.env` | Project + deployments |
| 2 | Model selection | Portal (Playground) | Reasoning (GPT-5.4 vs mini; optional Claude), fast extraction, **image** (MAI, seasonal/persona variants) via prompt engineering | Right-size by capability/cost/latency/quality |
| 3 | Build TrailMate v1 | VS Code | Run `build_agent.py`: create vector store, upload 10 manuals, create **prompt agent** with **file-search** + **frontier GPT** + instructions | Agent = model + instructions + tools; file-search grounding |
| 4 | Test & observe | Portal (Playground) | Ask TrailMate product questions; open **traces/metrics** (tool calls, latency, tokens, model) | Observability / AgentOps |
| 5 | Baseline eval | Portal | Run evaluation on v1 against the eval dataset; record scores = **altitude** | Measurable baseline, rubric dimensions |
| 6 | Lever 1 · Model Router | VS Code + Portal | Run `switch_to_router.py` (v2 references `model-router`); re-test; compare cost/latency/quality | Runtime model selection; a change counts only if quality holds |
| 7 | Lever 2 · Agent Optimizer | Portal | Follow the [optimize-prompt-agent quickstart](https://learn.microsoft.com/azure/foundry/agents/quickstarts/quickstart-optimize-prompt-agent): create rubric, run optimization, review candidates → v3 | Evaluation-guided instruction optimization |
| 8 | Compare & promote | Portal | Put v1/v2/v3 scores side by side; promote by evidence; recap **hill climbing** | Evidence-based decisions |

Steps 3–8 = the 45-minute agent segment.

## 6. Version ladder (documented for reproducibility)

Each change is one lever. This table is mirrored in `src/agent/VERSIONS.md` so the
climb is reproducible.

| Version | Name | Lever changed | Model | Instructions | Tool | Expected movement |
|---|---|---|---|---|---|---|
| v1 | Basecamp | starting point | `gpt-5-4` (frontier) | `instructions.md` (under-specified) | file-search | Baseline; capable model, weak instructions → grounding/citation/refusal gaps |
| v2 | Trailfinder | **model** → router | `model-router` | same as v1 | file-search (same vector store) | Cost/latency shift; quality should hold |
| v3 | Summit | **instructions** → optimized | `model-router` | optimizer-produced (ref: `instructions_optimized.md`) | file-search (same vector store) | Grounding + correctness + refusal improve |

> **v3 base = router (kept as-is).** Agent Optimizer optimizes the **instructions**
> on the `model-router` version. Note for learners: the optimizer setup can **also**
> explore **model** candidates — this is left as an **optional exercise** to try on
> their own after the guided climb, not part of the core 90 minutes.

Reproducibility rules:
- **Vector store + uploaded files are created once (v1)**; v2/v3 create new agent
  versions that **reference the same `vector_store_ids`** — no re-upload.
- The **eval dataset and rubric stay frozen** from the v1 baseline through v3.
- `VERSIONS.md` records: what changed, why, the exact model/instructions/tool per
  version, and how to reproduce each version from code or portal.

## 7. Evaluation data + rubric (designed for a real hill climb)

Aligned to the microsoft-foundry **observe** skill (built-in evaluators +
per-query `expected_behavior` rubric; custom evaluator output contract is
`result` + `reason`).

### Dataset — `src/data/evaluation-cases.jsonl`

8–10 cases, each `{"query": ..., "expected_behavior": ...}`, spanning the failure
modes v1 should struggle with and v3 should fix:

| Case type | Example query | What good looks like (rubric target) |
|---|---|---|
| Single-product grounded fact | "How waterproof is the TrailMaster X4 Tent?" | Cites the tent manual; states the actual spec; no invention |
| Cross-product discrimination | "For heavy rain, the Alpine Explorer or TrailMaster tent?" | Retrieves **both** correct manuals; compares on real specs |
| Unsupported info → refuse | "What's the warranty on the TrailLite Daypack?" | Says the manual doesn't cover it; doesn't fabricate |
| Category recommendation | "Recommend a sleeping bag for cold nights." | Uses CozyNights specs; grounded reasoning |
| Wrong-product trap | "What colors does the EcoFire tent come in?" | Notes EcoFire is a stove, not a tent; corrects gracefully |
| Format/persona | "Give a 2-line pitch for the Summit Breeze Jacket." | Concise, friendly, grounded, names the product |

### Rubric dimensions (frozen)

1. **Grounding & citation** (primary) — claims come from the retrieved manual(s);
   the right product is used; no fabrication.
2. **Correctness** — the specs/answer match the manual.
3. **Appropriate refusal** — when the manuals don't cover it, say so.
4. **Helpfulness / tone** — concise, friendly gear-guide voice; names the product.

### The TrailMate rubric evaluator (defined once, used everywhere)

We define **one custom rubric evaluator**, `trailmate_quality`, and use it
**consistently from the v1 baseline through v3** so the hill climb is measured the
same way every time. It scores against each case's `expected_behavior` (custom
evaluator output contract: `result` + `reason`).

- **Baseline (Step 5) uses the custom rubric** (not just built-ins), so the very
  first altitude reading and every later one share the same yardstick.
- Built-in evaluators (`relevance`, `task_adherence`, `intent_resolution`,
  `tool_call_accuracy`) run **alongside** it as supporting signals, but the
  `trailmate_quality` rubric is the **primary, frozen** measure for comparison.
- The rubric and dataset do **not** change between v1, v2, and v3.
- In Step 7, Agent Optimizer reuses this same rubric so its candidate scores are
  comparable to the baseline.

### v1 instructions (deliberately under-specified)

TrailMate v1 tells the model to "answer product questions using the files" but
**omits**: always cite the product/manual, refuse when unsupported, disambiguate
similar products, and keep answers concise. That creates measurable headroom.

### v3 optimized instructions (reference)

`instructions_optimized.md` adds: search the files first and cite the product;
if the manuals don't cover it, say so; disambiguate similar products by name;
answer concisely in a friendly gear-guide voice. This is the instructor
reference / fallback; the portal optimizer produces the learner's actual v3.

## 8. SDK and dependencies (from microsoft-foundry skill)

| Purpose | Package / API |
|---|---|
| Create vector store + upload manuals | data-plane `POST /vector_stores` (`api-version=v1`, auth resource `https://ai.azure.com`) |
| Create prompt agent (v1) + versions (v2) | `azure-ai-projects` (v2 preview, install `--pre`): `client.agents.create_version(agent_name, definition)` with `{"kind":"prompt","model":...,"instructions":...,"tools":[file_search with vector_store_ids]}` |
| Invoke for smoke test | `client.get_openai_client().responses.create(model=<deployment>, input=..., extra_body={"agent":{"name":...,"type":"agent_reference"}})` |
| Evaluation + Agent Optimizer | Portal (optimize-prompt-agent quickstart); built-in + custom rubric evaluators |
| Auth | `azure-identity` `DefaultAzureCredential` (via `az login`) |

`src/agent/requirements.txt` (floors confirmed at build via the skill):
`azure-ai-projects` (pre/2.x), `azure-identity>=1.25.0`, `python-dotenv>=1.1.0`,
`openai` (for the responses smoke test). **Note:** a prompt agent does **not**
need `agent-framework`/hosting packages — that was the LaunchPack (hosted) path
and is removed.
